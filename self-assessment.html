How the work fits together

CS-320 is the shape of a service: field rules, storage, HTTP, and a login. CS-300 is the choice of structure and the cost of that choice, including a schedule that has to respect prerequisites. CS-340 is where those ideas land in stored data: a collection, an index, a role, and a screen a staff member can open.

The Module Two code review walks the original Contact service. After that, each enhancement went on its own branch so a reviewer can diff it against main. I asked for comments on the auth filter, the median-first BST, and the unique index. The grades came back without a second code pass, so those branches are the enhanced work.

Grazioso staff need a filter they can open. dashboard.py is that screen. For a hiring manager, the same idea is the README at the top of each enhanced folder.

Outcome 5 is treating a record as something you protect on purpose. Contact exits if the staff and admin passwords are missing. A missing token is 401 with an empty body. A staff token on a write is 403 with an empty body. AnimalShelter does not connect when MONGO_USER and MONGO_PASS are empty. An empty lookup on delete returns 0.
